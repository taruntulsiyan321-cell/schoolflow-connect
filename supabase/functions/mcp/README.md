# mcp

## Recovered from production 2026-09-07 — deployed v5

`index.ts` is the source of deployed version 5, brought in with
`supabase functions download mcp` and copied without a character being retyped.
It was the last of two slugs `npm run check:edge-drift` reported as
**NO-REPO-SOURCE — deployed, and on no branch**. Both now have a home in git.

Downloaded mechanically on purpose. KNOWN_ISSUES 3 records why: the Management
API's `/functions/{slug}/body` returns a transpiled eszip, so a copy taken from
it looks authoritative and is subtly wrong, and retyping from a tool result is
the same hazard with a different cause. `check:edge-drift` reports no drift on
this file, which is the byte-comparison that proves the copy.

## Three things about it that are worth knowing before anyone touches it

**1. It is auto-generated by a plugin this repo does not have.** The banner says
`AUTO-GENERATED by @lovable.dev/mcp-js — do not edit. Regenerated by the Vite
plugin`, bundled from `src/lib/mcp/index.ts`. There is no `src/lib/mcp/`
directory on this branch, `@lovable.dev/mcp-js` is in no dependency list, and
`vite.config.ts` loads no such plugin. So the generator is gone and this file is
the only remaining artefact of it. Editing it by hand is possible — the banner
says deleting that first line takes ownership — but it is not currently being
regenerated by anything.

**2. Its OAuth issuer is a DIFFERENT Supabase project.**

```js
var projectRef = "kdmjipeksjdyojjdokbi";
auth.oauth.issuer({ issuer: `https://${projectRef}.supabase.co/auth/v1`, ... })
```

This project is `psqxykzqfvxgsvkmgurn` (`.env`, `supabase/config.toml:1`). So
the deployed function accepts tokens issued by another project's auth, and the
Supabase client it then builds points at *this* project's `SUPABASE_URL`. A
token from this project fails the issuer check; a token from that one would fail
this project's own JWT verification at PostgREST. **Not measured:** no call has
been made against it from here, so "it therefore returns nothing" is inference,
not a finding. What is measured is the mismatch itself.

**3. It has no caller.** Nothing in `src` invokes it — the same as
`ai-expand-questions`, `send-otp` and `verify-otp` (KNOWN_ISSUES 8b). Its seven
tools (`whoami`, `list_classes`, `list_students`, `attendance_summary`,
`student_marks`, `list_homework`, `list_notices`) are read-only and route
through the caller's own token, so they inherit RLS rather than bypassing it.

Recovered rather than deleted: deleting a deployed function is irreversible from
this repo. Whether an MCP endpoint pointed at another project should stay
deployed at all is a decision for someone who knows why it was pointed there.
